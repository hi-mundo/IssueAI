# Product and repository understanding phase

Build the product-understanding artifact before generating defect hypotheses.
Use the normalized repository, repository map, README/docs, public exports,
schemas, tests, configuration, package manifests and reference evidence in
authority order. Reconstruct product purpose, scope, capabilities, feature
ownership, technology stack, architecture, organization patterns, contracts,
observability and recurring implementation tendencies.

For every tendency, record exact evidence, observed frequency, local deviation,
likely maintenance/defect impact and confidence. Do not label a programmer or
invent a product rule. Record conflicts as open questions. The output must
conform to `schemas/product-understanding.schema.json`.
