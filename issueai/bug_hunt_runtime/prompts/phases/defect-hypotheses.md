# Defect hypothesis phase

Generate specific, falsifiable hypotheses tied to intent, repository nodes,
reference ids, triggers, and a validation method. Cover product, domain,
behavior, architecture, organization, convention, logic, typing, reliability,
and maintainability. A repeated repository pattern is evidence, not an
absolute rule. Mark inference when no reference applies. Do not label it a
finding.

Consume the bounded discovery worklist before opening arbitrary source files.
For every selected row, preserve the concrete source, transformation,
control/decision, state/resource, and effect tuple. Close four anchors before
calling it probe-ready: contract, exact boundary, escape-cell conjunction, and
falsifiable oracle. Keep the nearest passing sibling and common path as
negative controls. Expand shared helpers into concrete callers and independent
operations; a generic “cache issue”, “race condition”, or “compatibility bug”
is not a hypothesis.
